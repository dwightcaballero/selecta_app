SELECTA APP - AI DOCUMENT SCAN SPEED PLAN (FOR REVIEW)
======================================================

Problem: Scanning supplier invoices / purchase orders and store-order receipts
with Sedy AI takes about 2 minutes.
Note: Findings come from static code review. Phase 0 (timing logs) must confirm
which cause dominates before Phases 2-4 are tuned.

Scan flows affected (all go through lib/services/gemini_ai_service.dart)
- Store order receipt   : receipt_scan_flow.dart -> extractStoreOrderFromImages
- Supplier invoice / PO : purchaseorder_page.dart -> extractPurchaseOrderFromImages
- Invoice reconciliation: compareOfficialInvoiceWithPoItems
- Supplier stock / OOS  : supplier_oos_scan_dialog.dart, automated_po_suggestion_dialog.dart
                          -> extractSupplierStockStatusFromImages

Root causes found
1. GenerativeModel is built with no generationConfig (getModel, ~line 361):
   no responseMimeType JSON, no temperature, no maxOutputTokens. Flash models
   "think" by default, and google_generative_ai 0.4.7 has no thinkingConfig.
2. Whole inventory catalog (+ up to 70 alias lines) is pasted into every prompt.
3. prepareImageBytesForAi (helperfunctions.dart ~239) only compresses images
   over 2 MB, capped at 2200 px. Typical photos go up at full size.
   Long screenshots are sliced into up to 6 x 2400 px chunks (PNG -> JPEG).
4. visionTimeout = 120 s and timeouts count as "overloaded", so a slow call
   triggers model switch + another 120 s wait (up to 3 models).
   _activeModelIndex is reset to 0 after each success, so a bad first model
   (e.g. 404 on 'gemini-3.8-flash') is retried first on every scan.
5. Minor: checkAiAvailability = 2 sequential Firestore reads; getAllMappings;
   images read/compressed one by one. Roughly 1-3 s total.

TARGETS
-------
- Typical single receipt/invoice: under 15-20 s (from ~120 s)
- Multi-image (3-4 pages): under 30-40 s
- Worst case with one retry: under ~90 s
- No drop in quantity/product match accuracy

RISKS
-----
- Lower resolution may misread similar digits -> keep accuracy checks per phase
- maxOutputTokens too low truncates JSON -> test with the longest known receipt
- Catalog pre-filtering may hide the correct product -> fall back to full catalog
  when no confident match is found
- SDK migration (Phase 3A/B) touches all AI calls -> do last, behind a flag


RECOMMENDED ORDER
-----------------
Phase 0 -> Phase 1 -> Phase 2 -> Phase 4 -> Phase 3 -> Phase 5 -> Phase 6
(Phases 0-2 and 4 are small and should give most of the gain.)
