FUTURE-DATE BOOKING WITHOUT STOCK LIMIT - IMPLEMENTATION PLAN (FOR REVIEW)
==========================================================================

GOAL
----
When the delivery date of a Book Order transaction is TOMORROW OR LATER
(strictly after today), the user can book ANY active product at ANY quantity,
regardless of current stock. For TODAY (or past dates) the current stock-capped
behavior stays exactly as is.

BACKEND CHECK (verified - no blocker)
-------------------------------------
- DeliveryController.createBookedOrder (L563) / updateBookedOrder (L622) call
  InventoryService.reserveStockForOrder (L759) /
  adjustReservedStockForOrderUpdate (L853).
- reserveStockForOrder does NOT reject short stock. It still reserves,
  records a "short_allocation" discrepancy (L797-843), and reservedQuantity can
  exceed stock; availableQuantity is clamped to 0 in the models.
- Picklist already handles shortage (picklist_page.dart "CANNOT PICK -
  INSUFFICIENT STOCK", pick available units or 0, shortage printed on receipt).
- functions/src/index.ts only affects the store-facing catalog badge; unrelated.
So no server/Firestore rule change is required for the core feature.

DECISIONS (CONFIRMED BY USER)
-----------------------------
D1. Cap for future dates: high sentinel 99999 (user: value doesn't matter).
D2. Reservation: future orders KEEP reserving stock (unified pool). NO change
    to reserveStockForOrder / adjustReservedStockForOrderUpdate /
    releaseReservedStockForOrder accounting. Accepted side effect: a large
    future booking can make TODAY's available stock show 0 for those products.
D3. Short-allocation discrepancy: SKIP logging "short_allocation" for orders
    whose delivery date is after today (over-booking is expected). Today's
    orders keep logging it.
D4. Promos: LIFT the out-of-stock block on promo bundles for future dates.
    Today's orders keep the Q1 rule (blocked when OOS).
D5. "Hide Out of Stock" chip: IGNORED for future dates (items with 0 stock are
    always shown). Today's behavior unchanged.
D6. (Default, not contested) Cards show an informational pre-order label when
    a future-date item has no stock; real stock is shown when it has some.

RISKS / EDGE CASES
------------------
- Over-reservation makes today's availability 0 for those products (D2).
  Accepted by the user; mention in release notes.
- Date comparison uses device local date; midnight rollover while the page is
  open could leave a stale classification. Mitigation: getter is evaluated on
  each build, so it self-corrects; the clamp only runs on date change, so add
  a clamp when the order is saved (final guard): on save, if date is not
  future, re-run clamp and abort with message if quantities changed.
- Edit mode for an order whose date moves from future to today by the passage
  of time: the cap drops to available + alreadyInOrder on next edit. Good.
- Promo usage limits and totals are unaffected.
- Offline/duplicate-sync paths (offline_sync_deduplication_test) use the same
  controller; no signature break since the new param is optional.
