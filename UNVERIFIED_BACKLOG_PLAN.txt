UNVERIFIED BREAKDOWN BACKLOG - IMPLEMENTATION PLAN (FOR REVIEW)
================================================================

PROBLEM
-------
The End of Day badge shows a count of breakdown records not yet verified by
the dealer, but not WHICH days. Dealers cannot tell what to settle.

ALREADY DONE (previous step)
----------------------------
- lib/views/widgets/marked_date_picker.dart : month-grid picker, red dot on
  marked dates.
- BreakdownService.getUnverifiedBreakdownDates() : Set<DateTime> of all
  unverified dates (all months).
- EndofdayPage.onChangeDate uses the marked picker.

KNOWN INCONSISTENCY TO RESOLVE
------------------------------
The badge counts only the CURRENT MONTH (getUnverifiedBreakdownsCountStream /
getCountUnverifiedBreakdowns), but the calendar marks ALL months. Old backlog
is therefore invisible on the badge.
  RESOLVED: badge counts ALL unverified records within the last 3 months.

DECISIONS (confirmed by owner)
------------------------------
1. Badge counts ALL unverified days (not just current month).
2. Backlog scan window: last 3 months.
3. Badge is NOT tappable (too small, misclick risk). Instead: a large
   "Needs verification" banner card on the dashboard with a "Review" button
   (opens End of Day on the oldest unverified date), plus the date list and
   "Next unverified" button inside End of Day. Badge stays display-only and
   existing navigation (opens End of Day as today) is unchanged.
4. Verification must be oldest-first: on End of Day, verifying a date is blocked
   while an older unverified date exists (message names the oldest date and
   offers a "Go to oldest" action).
5. Age colours: amber at 2 days, red at 3+ days.
6. Expenses page: NOT implemented.
7. Reminders: IN-APP BANNER ONLY. No push notification, no Cloud Function,
   no backend, no Blaze plan, no extra cost. (Server push was considered and
   dropped by owner.)

PHASES (in recommended order; each is independently shippable)

  - Add model UnverifiedSummary { int count; DateTime? oldest; Set<DateTime> dates; }

    the dashboard DTO.
  - Dates normalised to local date-only (year, month, day).

PHASE 3 - "Next unverified" button on End of Day  [Rec #2]
